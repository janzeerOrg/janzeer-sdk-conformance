# Janzeer SDK conformance kit

The single source of truth that every official Janzeer SDK — and any third-party client — is tested against.
It contains **no node code**: only vectors generated by the node's own crypto and an end-to-end flow.

| Path | What |
|---|---|
| `vectors/wallet-parity-vectors.json` | Canonical crypto vectors (`vectorsVersion` 2): mnemonic → seed → HD key `m/0/0/0` → address; raw-key address; the signed preimage / double-SHA256 hash / RFC-6979 low-S DER-Base64 signature of every client-submittable transaction type (transfer with and without memo, validator registration, validator exit, token CREATE and TRANSFER); `addresses` (canonical lowercase vs EIP-55 display form); `scaled` (the `toScaledLong` 8-decimal table). |
| `vectors/vault-fixture.json` | Encrypted-mnemonic vault interop fixture (PBKDF2-HMAC-SHA256 250k + AES-256-GCM, blob `{v:1,salt,iv,ct}`): decrypting `blob` with `password` must yield `secret`; `wrongPassword` must fail. |
| `vectors/SHA256SUMS` | Checksums; `./sync.sh --check` verifies every vendored copy. |
| `e2e/SPEC.md` | The 14-step end-to-end flow every SDK implements as its e2e test (and trims into its README quickstart). |
| `e2e/node-up.sh`, `e2e/node-down.sh` | Boot / stop the local 4-anchor developer network with the faucet-funded test wallet (needs the private node repo as a sibling). |
| `sync.sh` | Copy the vectors into every SDK and app that vendors them (`--regen` regenerates them from the node first, `--check` verifies). |
| `run-all.sh` | Owner-only: every SDK's parity suite + e2e, and the apps' parity checks, against one running network. |

## Consuming the kit from an SDK

1. Vendor `vectors/*.json` into the SDK's test resources (the SDK repos keep them under `test/vectors/`).
2. The SDK's parity test must reproduce, for every entry: the seed, private/public key and address of `hd`; the address of
   `rawKey`; and for each `*Tx` entry the exact `preimageHex`, `hash` and `signature` from the listed fields. Assert
   `scaled[i].out == toScaledLong(scaled[i].in)` and `addresses[i].checksum == toChecksum(addresses[i].lower)`.
3. Vault: `decrypt(blob, password) == secret`; `decrypt(blob, wrongPassword)` throws.
4. Implement `e2e/SPEC.md` as an environment-gated test (`JANZEER_NODE_URL` unset → skipped).
5. CI: compare the vendored files' SHA-256 against `vectors/SHA256SUMS` (copy the file next to them) so drift fails the build.

## Facts the vectors pin (see the developer guide §3 and §5 for the full byte layouts)

- Seed: PBKDF2-HMAC-SHA512, 2048 rounds, 64 bytes, salt `@_Janzeer_Blockchain_@` + passphrase (not BIP39's `mnemonic`).
- HD root: HMAC-SHA512 keyed with `@_Janzeer_Blockchain_@`; path `m/0/0/0`, non-hardened, secp256k1, compressed keys.
- Address: `0x` + lowercase hex of the first 20 bytes of keccak256(compressed public key). EIP-55 casing is display only.
- Preimage: `networkId ‖ timestamp(8) ‖ scaled(fee)(8) ‖ nonce(8) ‖ senderAddress ‖ payload`, big-endian; networkId `janzeer`.
- Hash: double-SHA256, lowercase hex. Signature: ECDSA secp256k1, RFC-6979, low-S, DER, Base64, over the raw digest.
- Amounts: 8 decimals, HALF_UP, ×10^8 into an int64. Token amounts are integer base units carried as decimal strings.

## Networks

The kit is network-agnostic: `e2e/node-up.sh` boots the dev net on the mainnet id (`janzeer`) by default, or on the public
testnet id with `NETWORK=testnet` (`janzeer-testnet`, node 1 runs the faucet). It exports `JANZEER_NETWORK_ID`; SPEC step 2
makes every SDK read `networkId` from `GET /api/v1/info` and sign every transaction with it, so `run-all.sh` on both ids
proves the network knob end to end. The vectors stay on `janzeer`.

## Refreshing after a node change

```bash
./sync.sh --regen     # runs WalletParityVectorsTest in ../backend_v03, copies the output everywhere, refreshes SHA256SUMS
./e2e/node-up.sh && ./run-all.sh; ./e2e/node-down.sh
```
